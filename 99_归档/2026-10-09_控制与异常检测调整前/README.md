## 文件管理约定

1. **原始材料保持原样。** 新的需求理解与修改放在“整理稿”或“确认记录”，不直接覆盖导师原始要求。
2. **每类成果保留清晰的当前工作稿。** 当前开题稿保留既有文件名，避免出现多个不明确的“最终版”。
3. **阶段快照使用日期和版本号。** 示例：`开题报告_2026-10-03_v01.docx`；旧版移入归档，当前工作目录不堆积历史副本。
4. **正式材料与草稿分开。** 经确认的材料放入对应“定稿”目录；真正提交的副本放入“07_答辩与提交/提交材料”，不把未审阅草稿标成定稿。
5. **配图跟随文档。** Markdown 使用相对路径引用配图；搬移文档时连同配图目录一起搬移。Word 中嵌入的图片与外部图片不是自动同步关系。
6. **参考资料记录来源。** 文献、数据手册保留标题、作者或机构、版本、DOI或来源地址及获取日期，不与本人设计成果混放。
7. **实验数据与实现保持可追溯。** 文档使用的数据快照、图表和报告按实验编号保存，不覆盖已有记录；记录实验条件、采集日期与对应实现版本。采集及处理脚本在实现项目中维护，不复制到本文档目录。
8. **代码与文档分开管理。** 系统实现统一维护在 `D:\USERS\Devil\Desktop\CODE\Project\Final-Year-Project`，本文档目录不新增源码工程、依赖、构建产物或运行配置；账号密钥不写入报告或提交材料。
9. **提交材料来自明确版本。** 文档引用实现成果时，注明对应版本或提交标识（若项目使用版本控制）。仅在学院明确要求时，将指定版本的代码压缩包作为提交附件放入“07_答辩与提交/提交材料”，不在此维护第二份开发工程。
