# 手冲咖啡系统异常检测算法选型比较

> 研究日期：2026-10-09；本轮选型补充：2026-10-10。状态：方案研究稿，待导师确认、待本项目实测。  
> 本文回答：Isolation Forest 是否是兼顾实用性、工作量与复杂度的最佳选择？  
> 资料边界：核对官方文档、GitHub API、项目 README 和指定版本的相关源文件；未运行这些项目，也没有本项目检测效果数据。

> **本轮最终建议（2026-10-10）：采用“阶段规则 + 分阶段残差 + MAD/分位阈值 + EWMA”作为主方案，不把机器学习列为必做；Isolation Forest 仅保留为有余力时的云端扩展。**

## 1. 结论与选型状态

**不能认定 Isolation Forest 是本项目“实用性最好”的异常检测算法。**目前缺少本项目真实数据、明确的异常定义和同条件对比实验。较高星级只表示社区关注，不能证明算法适合手冲咖啡，也不能保证检测准确率。

针对“好用、好做、能完成验收”的目标，当前建议为：

- **主方案：设备端状态规则保护 + 分阶段残差 + 中位数/MAD或分位数阈值 + EWMA + 持续时间/迟滞判定。**这不依赖机器学习，能覆盖安全故障和主要过程偏离，优先实现。
- **可选扩展：云端 Isolation Forest。**只有在数据记录和云端分析已经稳定、且仍有时间时再加入，用于补充识别多个参数共同偏离。
- **不再继续扩展候选：ECOD、HBOS、LOF、One-Class SVM、在线森林等。**它们可以写入比较表，但不值得在本项目中额外实现。
- **不建议当前引入：大规模聚类平台、深度自编码器/LSTM、LLM逐采样诊断。**这些不是本项目最低验收所需，增加部署或验证负担。

这不是用规则代替已获批准的机器学习要求；当前任务书尚未确定，是否必须包含机器学习内容应由导师确认。

### 1.1 根据导师要求收敛后的结论

导师对算法没有“必须使用机器学习”或“必须达到某个模型指标”的硬性要求，因此不再为了形式上的机器学习增加实现范围。对本项目而言，最实用的选择是：**先实现可解释、可标定、可在 STM32 与云端配合运行的规则/统计方案；Isolation Forest 不作为必做项。**

选择理由：

1. 手冲过程具有预热、闷蒸、分段注水、停水滴滤等阶段，同一数值在不同阶段可能分别代表正常和异常；阶段语义比模型复杂度更重要。
2. 当前主要异常可以直接表达为超限、持续无流量、称重失效、目标偏差过大、流量与增重不一致等规则和残差问题。
3. 中位数/MAD或分位数阈值实现短、对少量正常数据较友好；EWMA进一步检测持续漂移，异常原因仍可直接解释，便于导师验收和论文展示。
4. 模型真正耗时的部分不是调用接口，而是采集正常会话、切分阶段、处理时间对齐、选择阈值和做独立测试；当前没有必要承担这部分额外风险。

因此，最终路线不是“简单阈值凑数”，而是“安全规则 + 阶段化统计检测 + 事件记录 + 实验验证”。这已经能够形成完整的异常检测模块。

### 1.2 如果后续想顺手加入一项机器学习算法

**只考虑云端 Isolation Forest，且把它定义为可选实验，不改变主方案。**它不进入 STM32 实时控制回路，也不直接触发紧急停机。

建议采用以下收敛方案：

1. 本地规则仍负责超温、传感器失效、无流量和称重异常等安全动作；
2. 只采集正常完整冲煮会话作为初始基线，先完成清洗、阶段切分和特征计算；
3. 仅在云端稳定注水阶段尝试模型，特征控制在温度偏差、流量偏差、单位时间重量增量、执行器状态等少量变量；
4. 用独立会话而不是相邻窗口随机切分进行测试；
5. 模型只输出“异常评分/疑似偏离”，由规则和事件记录解释原因，不能直接触发紧急停机。

**实际省时判断：**Isolation Forest的代码本身不长，真正耗时的是数据采集、阶段语义、阈值标定和测试。如果已有Python后端、历史曲线和正常样本，增加一个云端实验模块通常比在STM32上实现复杂算法省时；如果还没有稳定数据管线，先做规则基线和数据记录更省时，不能为了“加入机器学习”反过来拖慢主线。

### 1.3 最终推荐顺序

| 优先级 | 方案 | 适合当前课题的理由 | 是否建议写入任务书 |
|---|---|---|---|
| 1 | 阶段规则＋分阶段残差＋MAD/分位阈值＋EWMA | 不需训练，适合小样本，解释、标定和答辩最简单；可直接连接故障码和安全动作 | **最终选定，建议作为必做** |
| 2 | 规则基线＋云端 Isolation Forest | 有余力时可补充识别多个连续变量的组合偏离，但不影响主线交付 | **可选扩展，不作为必做** |
| 3 | 规则基线＋ECOD 或 HBOS（二选一） | 参数较少，但引入额外依赖和验证工作；收益不如直接做好统计基线 | 不实现，仅保留在比较表 |
| 4 | 残差 CUSUM | 不属于机器学习，对持续小偏差敏感，但参数调试多于EWMA | 作为论文备选增强，不纳入首版实现 |
| 5 | LOF / One-Class SVM | 需要更多邻域、核函数、缩放或阈值调节；对当前小型过程数据的收益不确定 | 当前不建议 |

不建议同时实现 Isolation Forest、ECOD、HBOS、k-means 和在线森林。对本课题而言，最多保留“规则/统计基线 + 一个机器学习候选”的对照结构，避免把依赖、参数和实验解释负担叠加到主线。

## 3. 为什么本项目不宜一开始就锁定孤立森林？

本项目的过程并不是一种稳定状态：预热时温度上升、闷蒸等待时无流量、停水后仍可能滴滤，都是正常行为。同一温度、流量或重量变化，在不同阶段可能有完全不同的意义。

因此，模型或阈值之前应先定义：

1. 数据所在阶段、阶段目标和执行器是否开启；
2. 实际测的是累计注水增重还是成品液重；
3. 采样时间对齐、传感器有效性、滤波与执行响应延迟；
4. 需要停机的安全异常与仅需记录的过程偏离。

**没有阶段语义，换成更复杂的模型也不一定能减少误报。**这一点是本项目方案判断，不是已完成的实验结论。

## 4. 候选方法的成本与适用性比较

| 方法 | 本项目中的作用 | 数据/实现负担 | 局限与当前建议 |
|---|---|---|---|
| 状态规则 + 持续时间 + 迟滞 | 超温、读数无效、出水命令生效后长期无流量、重量跳变等 | 不需训练；需调试阈值、响应延迟和故障码 | 最容易解释并验证；必做基线，不能覆盖所有未知异常 |
| 分阶段残差 + 中位数-MAD/分位数 | 检测目标偏差、采样跳变、与同阶段正常曲线不一致 | 只需正常基线、窗口和阈值；MAD为0需设置最小尺度 | 当前最值得先做的非机器学习方法；结果可直接解释为“偏离阶段基线多少” |
| EWMA/CUSUM 作用于残差 | 检测持续漂移、流量逐渐变小、温度响应变慢等时间变化 | 需设置平滑系数、参考值、累计阈值和复位规则 | 适合发现持续偏离，不适合单独处理传感器失效或瞬时硬故障；作为统计增强 |
| Isolation Forest | 识别温度偏差、流量偏差、重量增长和执行器状态的组合偏离 | 需正常基线、特征处理、独立验证会话和阈值标定；标准算法不自动理解时间顺序 | 若要加一项云端无监督算法，是最稳妥的候选；不是已证实最佳，也不能输出故障根因 |
| ECOD | 按各特征经验分布的尾部程度形成异常评分 | 参数调节少，但仍需阶段处理、基线和判定阈值；若使用PyOD会增加依赖 | 适合做轻量对照；特征之间的组合关系和时间顺序不能直接由它解释 |
| HBOS | 用各特征直方图/分布偏离构造快速异常分数 | 实现和计算都较轻，但需分箱、特征尺度和正常分布稳定 | 可作为极简对照；特征相关性较强时不能把结果解释成完整联合分布 |
| k-means + 距离阈值 | 样本距离正常簇的偏离 | 需特征缩放、簇数/模型窗口和距离阈值 | Netdata有工程先例，但其平台配置不能直接套到咖啡过程；不作为本项目首选 |
| LOF | 识别局部密度明显稀疏的样本 | 需邻居数、距离尺度和足够的参考样本；对新数据要区分训练/新颖性检测模式 | 对阶段切换、样本量和阈值较敏感；当前不如IF容易收敛 |
| One-Class SVM | 用边界包围正常样本 | 需缩放和调节 `nu`、核函数及 `gamma`；样本分布变化会影响边界 | 理论上可行，但调参和解释成本高于当前收益，暂不优先 |
| Half-Space Trees | 持续流数据的在线异常评分 | 需特征范围、预热窗口、在线更新及异常数据污染控制 | 当前无在线适应需求，不优先；先完成离线会话验证 |
| 自编码器/LSTM | 复杂数据或序列模型 | 网络、训练、数据量和部署验证负担较大 | 与当前省时目标不匹配，不作为本版承诺 |

表中复杂度和优先级是针对本课题的工程评估；不能作为普遍算法性能排名。

### 4.1 本轮最值得比较的路线

**路线 A：规则 + 分阶段残差统计（不含机器学习）**

- 用阶段目标曲线或稳定注水阶段的正常统计量生成残差；
- 用中位数和 MAD（或分位数）给出稳健阈值；
- 对连续偏离使用 EWMA 和持续时间判定；
- 直接输出“温度偏离、流量偏离、重量变化不一致”等可解释事件。

这条路线不需要训练复杂模型，最适合当前还没有大量完整异常样本的情况。它的工作量主要落在阶段划分、信号对齐、标定、故障注入和误报分析，足以形成完整的算法设计与实验内容。

**路线 B：规则 + Isolation Forest（需要机器学习时的首选）**

- 只在云端、离线或准实时分析；
- 用会话/阶段窗口的少量特征，不直接把原始高频序列全部送入模型；
- 训练集和测试集按完整会话隔离；
- 规则负责硬故障，模型负责“多个变量一起偏离但单项尚未超限”的提示。

**路线 C：规则 + ECOD 或 HBOS（只做轻量对照）**

- 适合验证“单变量尾部偏离是否已经足够”；
- 若数据量小、特征关系不稳定，简单分布评分可能比复杂模型更容易解释；
- 仍需做阶段处理和独立测试，不能因为参数少就跳过验证；
- 只选一个，不与 Isolation Forest 同时作为产品功能部署。

### 4.2 暂不优先 LOF 和 One-Class SVM 的理由

这两类方法并非错误，而是与当前项目的约束不匹配：LOF依赖局部邻域结构，阶段切换会改变邻域密度；One-Class SVM对特征缩放、核函数和 `nu`/`gamma` 等参数更敏感。两者都可能在整理数据后作为论文讨论对象，但不值得在主线早期投入调参时间。

### 4.3 最小对比实验

如果后续有余力或导师希望看到算法对比，建议只做以下三种配置，且使用同一批会话级数据；主线交付不依赖第 3 项：

1. **规则基线**：阶段规则 + 持续时间/迟滞 + 一致性检查；
2. **规则 + 统计**：规则基线 + 分阶段残差 MAD/分位阈值 + EWMA；CUSUM只作为后续备选；
3. **规则 + 一个模型**：优先 Isolation Forest；若导师更看重极简实现，则将其替换为 ECOD 或 HBOS。

三种配置使用相同的异常注入/故障模拟类型、相同的会话级训练测试切分和相同的评价指标。若模型没有在独立会话上降低误报、缩短检出延迟或增加可检出的异常类型，就保留对比结果而不把模型写成核心功能。

## 5. 建议的最小实现

### 5.1 设备端：独立且必做的规则保护

每条规则明确：启用阶段、输入有效性、触发条件、持续时间、恢复条件、故障码、执行动作。

- 温度读数失效或超过确认限值：停止加热，按故障等级处理出水；
- 在应当出水且已过响应宽限期的阶段持续无流量：停止当前过程并告警；
- 称重读数失效、严重跳变或长期不符合注水变化：暂停或停止定量注水；
- 达到目标注水量：正常完成，不作为异常；
- 远程命令过期、重复或设备未准备：拒绝启动；
- 断网：按已确认的本地流程运行和缓存，不自动重放过期命令；
- 基础看门狗与异常状态处理：结合主控和驱动实现，不能替代独立电气保护。

用迟滞、持续判定和阶段切换宽限期降低噪声误报。具体限值通过标定和导师确认，不照抄意式咖啡机的温压上限。

### 5.2 云端：参数一致性与事件记录

- 计算当前阶段的温度偏差、流量偏差、重量增长变化和执行器状态；
- 在称重结构确实能测量累计注水增重、时间对齐有效时，比较流量积分与增重；质量/体积换算使用经确认的密度近似或标定关系，并设置传输与响应延迟容差；
- 对偏离先记录和解释，不让云端分析直接承担实时紧急停机；
- 小程序显示“可能流量受限/可能称重扰动”等提示，不把相关性判定写成确定故障根因。

### 5.3 本轮最终选定方案的具体做法

先按阶段建立正常基线，再对每个采样点或短窗口计算残差。设阶段为 `s`，目标值或正常基线为 `b_s(t)`，观测值为 `x_t`，则：

```text
r_t = x_t - b_s(t)
center_s = median(r_t)
MAD_s = median(|r_t - center_s|)
scale_s = 1.4826 × max(MAD_s, 最小尺度)
```

初始判定可使用 `|r_t - center_s| > k × scale_s`，其中 `k` 先作为标定参数，不直接宣称固定为某个“标准值”；在正常完整会话上选择能控制误报的阈值。对于流量和重量等有方向的指标，可分别设置“过小”和“过大”阈值。

对稳健标准化残差 `z_t` 再计算 EWMA：

```text
EWMA_t = λ × z_t + (1 - λ) × EWMA_(t-1)
```

`λ`、触发阈值和恢复阈值通过正常会话与安全故障模拟标定；阶段切换时重新初始化或按阶段保存状态，避免把预热阶段的偏差带入注水阶段。

工程上按以下顺序实现：

1. **阶段识别**：预热、闷蒸、注水、停水/滴滤、完成等阶段分别处理，不把阶段编号直接当连续数值输入。
2. **信号有效性**：先检查传感器断线、越界、冻结、突跳和时间戳异常，再计算残差。
3. **残差检测**：温度、流量、称重分别计算阶段残差；流量积分与称重增量的比较要加入响应延迟和标定误差容差。
4. **持续判定**：异常需连续超过若干采样点或持续一定时间才升级为过程事件；安全硬故障仍由本地规则立即处理。
5. **迟滞恢复**：设置触发阈值和恢复阈值，避免数值在边界附近反复报警。
6. **事件输出**：保存阶段、传感器、残差、阈值、持续时间、故障等级和处理动作，便于小程序展示和论文统计。

EWMA作为首版统计检测的一部分，用于识别“逐步变慢/持续漂移”；CUSUM先不实现，只有在测试显示EWMA不足时再考虑。

### 5.4 如果最终选择 Isolation Forest

将它限制在一个云端模块内，不向STM32移植森林，不添加在线训练平台，不做多模型自动选择。

建议使用目标残差、变化率、窗口统计等少量特征；按阶段建立合理基线或先限制为稳定注水阶段。不要简单把阶段编号当连续数值输入，假定模型能自动理解阶段含义。

- 正常运行数据用于拟合；独立会话用于阈值标定和测试；
- 不把同一会话相邻窗口拆到训练集和测试集，避免泄漏；
- 不把大量相关窗口当作大量独立实验；
- 固定随机种子、模型参数、特征版本与阈值版本；
- `contamination`不能凭空当作真实故障比例；判定阈值需校准；
- scikit-learn的`score_samples`越低越异常，PyOD通常约定分数越高越异常；封装时统一方向；
- 异常分数不等于故障概率，显示0～1归一化值也不能宣称概率；
- 模型仅提供异常评分，原因解释依赖阶段规则和实测；
- 若模型对独立测试的增益不足，可保留实验比较和不采用结论，但前提是导师未把部署该模型确定为必做项。

## 6. 足够工作量应由完整证据链体现

不需要靠增加多个机器学习模型凑工作量。以下可以形成实质性设计和测试内容：

- 故障规则表和异常状态机；
- 阈值、迟滞和响应宽限期的标定；
- 多传感器时间对齐和一致性检查；
- 故障事件上报、保存及小程序展示；
- 正常完整会话与安全故障模拟测试；
- 误报、漏报和检出延迟分析；
- 如有余力选用孤立森林，再比较“规则/统计基线”和“规则/统计基线+模型”对同一独立测试集的效果；没有增益时不部署。

异常测试优先通过信号注入、传感器数据模拟或受限功率/冷水测试完成。不得通过真实干烧、危险过温或破坏设备制造故障。

评价建议按事件统计检出率、误报事件数/正常会话和检出延迟，并列出测试异常类型及次数。若有样本标签，可补充精确率、召回率和F1；不以高度不平衡数据上的总准确率作为唯一效果指标。无明确异常标签时，不虚构准确率。
