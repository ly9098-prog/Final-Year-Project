# 毕业设计提交文档工作目录

**当前建议课题：基于 STM32 的手冲咖啡温控与定量注水及萃取管理系统设计与实现（待导师确认）**

当前控制方案为温度PID＋流量PID＋称重反馈定量控制，不承诺第三个PID。过程管理以真实记录和分段配方重复执行为范围；异常检测主线采用阶段规则＋分阶段残差＋MAD/分位阈值＋EWMA。导师原始材料保持不变。

本目录主要用于毕业设计提交文档及其支撑材料，包括需求与任务材料、开题报告、参考文献、设计说明、实验记录、毕业论文及答辩材料；另设 `05_STM32_Code`，作为 STM32 固件源代码的专用目录。除该目录外，不在文档工作区维护其他系统源码或完整可运行工程。

**目录命名约定：** 所有文件夹统一使用 ASCII 英文、数字和下划线命名，以减少 Windows、WSL、脚本和工具链之间的兼容问题；现有文档、图片和资料文件名暂保持原样，避免影响资料识别与历史记录。

## 文件管理约定

1. **原始材料保持原样。** 新的需求理解与修改放在“整理稿”或“确认记录”，不直接覆盖导师原始要求。
2. **每类成果保留清晰的当前工作稿。** 当前开题稿保留既有文件名，避免出现多个不明确的“最终版”。
3. **阶段快照使用日期和版本号。** 示例：`开题报告_2026-10-03_v01.docx`；旧版移入归档，当前工作目录不堆积历史副本。
4. **正式材料与草稿分开。** 经确认的材料放入对应“定稿”目录；真正提交的副本放入“07_Defense_and_Submission/提交材料”，不把未审阅草稿标成定稿。
5. **配图跟随文档。** Markdown 使用相对路径引用配图；搬移文档时连同配图目录一起搬移。Word 中嵌入的图片与外部图片不是自动同步关系。
6. **参考资料记录来源。** 文献、数据手册保留标题、作者或机构、版本、DOI或来源地址及获取日期，不与本人设计成果混放。
7. **实验数据与实现保持可追溯。** 文档使用的数据快照、图表和报告按实验编号保存，不覆盖已有记录；记录实验条件、采集日期与对应实现版本。采集及处理脚本在独立的测试工程中维护，不放入 `05_STM32_Code`。
8. **代码按用途隔离管理。** STM32 固件源码及必要工程配置维护在 `05_STM32_Code`。实验记录、报告和提交材料不混入代码目录；账号密钥不得写入代码或文档。
9. **提交材料来自明确版本。** 文档引用实现成果时，注明对应版本或提交标识（若项目使用版本控制）。仅在学院明确要求时，将指定版本的代码压缩包作为提交附件放入“07_Defense_and_Submission/提交材料”；该副本仅用于提交，不作为日常开发工程。
